# ชั้นความน่ากลัวบนหน้าแรก (Scare Layer) — เอกสารออกแบบ

วันที่: 2026-11-08 · สถานะ: รออนุมัติ (ผ่าน builder check แล้ว)

## ทำไปเพื่ออะไร

เว็บขายบัตรบ้านผีสิงตอนนี้สวยแต่ไม่น่ากลัว เจ้าของงานอยากให้คนที่เปิดเว็บบนมือถือรู้สึก **ขนลุก** แบบค่อย ๆ ซึม ไม่ใช่โดนผีโผล่ตุ้งแช่ให้สะดุ้ง แรงบันดาลใจมาจากเทคนิคในหนังผีไทย 3 เรื่อง: ชัตเตอร์ กดติดวิญญาณ (2547), ธี่หยด (2566), ร่างทรง (2564)

หลักของทั้งสามเรื่องที่เอามาใช้: ผีไม่ได้อยู่ให้เห็นชัด แต่โผล่แวบเดียว หรือมารู้ตัวทีหลังว่ามีอะไรบางอย่างอยู่ตรงนั้น

## เป้าหมาย

1. **หน้าประตู + เสียงกระซิบ** — เข้าเว็บครั้งแรกต้องแตะ "เข้าบ้าน" เสียงกระซิบดังทันที แล้วสุ่มดังเป็นระยะเมื่อแตะหรือเลื่อนจอ
2. **ร่างชุดดำที่ใกล้ขึ้นทุกครั้งที่กลับมา** (ใน hero) — เทคนิคจากธี่หยด
3. **กล้องแฟลชเผยผี + โพลารอยด์** (แทน section รูป 3 ใบ) — เทคนิคจากชัตเตอร์
4. **ตอนจบที่เชื่อม 2 กับ 3** — เมื่อร่างมาถึงระยะใกล้สุด มันหายไปจาก hero แล้วไปโผล่ในรูปแฟลชครั้งถัดไป ผ่านเงาในกระจก ว่ายืนอยู่ข้างหลังคนดู

## สิ่งที่ไม่ทำ (non-goals)

- ไม่ทำลูกเล่นแบบ 2 (แถบฟิล์ม), 5 (กล้องวงจรปิด), 6 (นับคืน) จากม็อก — เจ้าของงานเลือกแค่ 1, 3, 4
- ไม่ใส่ลูกเล่นในหน้า `/booking`, `/checkout`, `/ticket`, `/ticket/[studentId]`, `/admin/*`
- ไม่ใช้กล้องหรือไมโครโฟนของผู้ใช้
- ไม่แก้ flow ซื้อบัตร, API, หรือ backend

## สิ่งที่ห้ามเกิด (anti-goals) — ถ้าเกิดถือว่าล้มเหลวแม้จะทำงานได้

- **ใช้ของจากหนัง:** ห้ามใช้ชื่อ ตัวละคร ภาพ เสียง ดนตรี คำพูด (เช่นคำว่า "ธี่หยด") หรือหน้าตาผีจากหนัง ผี เสียง และภาพทั้งหมดต้องสร้างขึ้นเอง ห้ามเอ่ยชื่อหนังบนเว็บ
- **ขวางการซื้อบัตร:** ปุ่ม "จองบัตร" ต้องกดได้ทันทีหลังผ่านหน้าประตู ไม่มีลูกเล่นใดบังหรือหน่วงทางไปหน้าจอง
- **ตุ้งแช่/น่ารำคาญ:** ไม่มีเสียงดังกระแทก ไม่มีภาพเด้งเต็มจอ เสียงกระซิบไม่ดังติด ๆ กัน
- **อันตรายต่อผู้ที่ไวต่อแสง:** แฟลชห้ามกะพริบเกิน 3 ครั้ง/วินาที (WCAG 2.3.1)
- **หน่วงเครื่อง:** หน้าแรกต้องยังลื่นบนมือถือ Android ระดับกลาง ไม่ทำให้ข้อความและปุ่ม hero แสดงช้าลง

## ข้อจำกัด

- โปรเจกต์: Next.js 16.4.5 (App Router, `cacheComponents: true`), React 19.3, `motion`, `lucide-react`, Tailwind 4 + `app/globals.css` (โปรเจกต์มี `AGENTS.md` บอกให้อ่านเอกสาร Next ใน `node_modules/next/dist/docs/` ก่อนเขียนโค้ด เพราะ API ต่างจากเวอร์ชันเก่า)
- ผู้ชมหลัก: นักศึกษา เปิดบนมือถือเป็นส่วนใหญ่ มักเปิดในห้องเรียนหรือบนรถ
- เบราว์เซอร์ไม่ให้เล่นเสียงก่อนผู้ใช้แตะ/คลิก/กดปุ่ม (การเลื่อนจอไม่นับ) — เป็นเหตุผลของหน้าประตู
- รูปบ้านผีสิงจริงจะถ่ายในวันงานและเพิ่มภายหลัง ตอนนี้ใช้รูป mock ใน `public/images/` (`mansion.jpg`, `hallway.jpg`, `room.jpg`, `ritual.jpg`)
- ข้อความบนเว็บเป็นภาษาไทยเป็นหลัก (ตามงานก่อนหน้า)

## ม็อกอ้างอิง

ม็อกที่เจ้าของงานกดเล่นและเลือกแล้ว อยู่ที่ `.superpowers/brainstorm/98990-1794131808/content/scare-mocks.html` (ไม่อยู่ใน git — อยู่ในเครื่อง) แท็บ 1, 3, 4 คือของที่เลือก ใช้เป็นตัวอ้างอิงความรู้สึก ไม่ใช่โค้ดที่จะยกไปใช้ตรง ๆ

## รายละเอียดที่เจ้าของงานตัดสินใจแล้ว

### 1. หน้าประตู

- เข้าเว็บครั้งแรก (ที่หน้าใดก็ได้ที่เป็นหน้าแรก `/`) เจอจอมืดเต็มจอ มีปุ่ม "เข้าบ้าน"
- แตะปุ่ม → เสียงกระซิบแรกดังทันที → หน้าเว็บค่อย ๆ เปิดออก
- ขึ้นแค่ครั้งแรก ครั้งต่อไปเข้าหน้าแรกได้เลย (จำไว้ในเครื่อง) และเสียงจะเริ่มทำงานเมื่อแตะครั้งแรก
- ต้องมีปุ่มปิดเสียงที่เห็นชัดตลอด และจำค่าไว้
- ปุ่ม "เข้าบ้าน" บอกชัดว่าจะมีเสียง ข้าง ๆ มีปุ่มเล็ก "เข้าแบบไม่มีเสียง" (เข้าแบบนี้ = ปิดเสียงไว้ตั้งแต่ต้น เปิดทีหลังได้จากปุ่มเสียง)
- **iPhone โหมดเงียบ:** เมื่อผู้ใช้เลือก "เข้าบ้าน" (เลือกฟังเสียงเอง) ให้เสียงดังข้ามโหมดเงียบ ด้วย `navigator.audioSession.type = "playback"` ในเบราว์เซอร์ที่รองรับ ถ้าไม่รองรับก็ปล่อยตามค่าปกติของเครื่อง

### 2. เสียงกระซิบ

- หลังเข้าบ้าน ทุกครั้งที่แตะหรือเลื่อนจอ มีโอกาสสุ่มให้เสียงกระซิบดัง
- เสียงมาจากทิศต่าง ๆ (ซ้าย ขวา หลัง) บางครั้งมาจ่อใกล้หูข้างเดียว — ใช้ Web Audio `PannerNode` แบบ HRTF เหมือนม็อก
- เสียงเป็นลมหายใจกระซิบไม่เป็นคำ สร้างเอง
- ตัดเอฟเฟกต์ภาพเบลอ "ง่วง" ในม็อกออก — เสียงอย่างเดียว
- มีระยะพักขั้นต่ำระหว่างเสียง (ประมาณ 15 วินาที) กันเลื่อนรัวแล้วดังติดกัน

### 3. ร่างชุดดำใน hero

- แทนรูป `mansion.jpg` ใน hero ด้วยฉาก Three.js: ทุ่งหมอกยามค่ำ ต้นไม้ และร่างชุดดำยืนใต้ต้นไม้ไกล ๆ (แบบแท็บ 3 ในม็อก)
- ข้อความ ปุ่ม และ layout ของ hero (ชื่อเรื่อง, "บ้านผีสิง", ปุ่ม "จองบัตร") คงเดิม วางทับบนฉาก
- ร่างไม่ขยับระหว่างที่คนดูอยู่ ขยับเข้ามาใกล้ขึ้นหนึ่งระยะทุกครั้งที่คน "กลับมา": สลับแท็บแล้วกลับมา หรือเปิดหน้าแรกใหม่
- ตำแหน่งจำไว้ในเครื่อง ข้ามการเข้าเว็บแต่ละครั้ง
- _(Claude ตัดสินใจ)_ นับว่า "กลับมา" เฉพาะเมื่อหายไปนาน ≥ 20 วินาที (กันจอดับ/แวบไปอ่าน LINE แล้วเดินถึงตัวในนาทีเดียว) และการขยับจะเกิดให้เห็นตอนที่ hero อยู่บนจอเท่านั้น ถ้ากลับมาตอนเลื่อนลงไปแล้ว ให้ค้างไว้จนกว่าจะเลื่อนกลับขึ้นมาเห็น hero

### 4. กล้องแฟลช + โพลารอยด์ (เจ้าของงานเลือก: รูปจริง + ผีซ้อน)

- แทน section `#experiences` (รูป 3 ใบ) ในหน้าแรก
- ฉากคือ **รูปถ่ายบ้านผีสิงจริง** (ตอนนี้ใช้ mock `hallway.jpg`, `room.jpg`, `ritual.jpg`) แสดงแบบมืดเกือบมองไม่เห็น ไม่ใช่ห้อง 3D แบบในม็อก
- กดชัตเตอร์ → แฟลชทำให้รูปสว่างแวบสั้น ๆ พร้อมผีที่ออกแบบเองซ้อนบนรูป (สุ่มประมาณครึ่งหนึ่ง) → ได้โพลารอยด์ของภาพตอนแฟลช ค่อย ๆ ล้างออกมา และในรูปยังเห็นผี
- แต่ละครั้งที่กดใช้รูปถัดไปในชุด
- ผีวาดซ้อนเป็น 2D (canvas หรือ CSS) ก็พอ ไม่ต้องมีฉาก WebGL ที่สอง (hero ใช้ WebGL อยู่แล้ว)
- รายชื่อรูปและตำแหน่งที่ผียืนได้ในแต่ละรูป ให้อยู่ใน config ไฟล์เดียว (เช่นเดียวกับ `lib/event-config.ts`) เพื่อให้วันงานแค่วางรูปใหม่ใน `public/images/` แล้วแก้ config ไม่ต้องแก้โค้ด

### 5. ตอนจบ (เชื่อม 3 กับ 4)

- เมื่อร่างมาถึงระยะใกล้สุดแล้ว การกลับมาครั้งถัดไปทุ่งหมอกว่างเปล่า
- แฟลชครั้งถัดไปในส่วนกล้อง **ติดผีแน่นอน** โดยใช้ **รูปกระจกบานใหญ่** ในบ้านผีสิง: ในกระจกเห็นร่างชุดดำยืนอยู่ตรงตำแหน่งคนดู = มันอยู่ข้างหลังคุณ
- รูปกระจก: ทีมงานถ่ายในวันงาน ระหว่างนี้ใช้รูป mock (สร้างหรือหามาเองที่ใช้ได้ถูกต้อง) config ต้องระบุกรอบของกระจกในรูป เพื่อวางร่างให้อยู่ในกระจกพอดี
- จากนั้นร่างกลับไปยืนไกลใต้ต้นไม้ เริ่มวนใหม่

### 6. ความปลอดภัยและเครื่องสเปกต่ำ _(Claude ตัดสินใจ)_

- `prefers-reduced-motion`: ยังได้ทุกลูกเล่น แต่ฉาก hero ไม่ส่าย, แฟลชไม่ขาวจ้าเต็มจอ (สว่างแค่ในกรอบรูป), หน้าประตูเปิดแบบไม่มี animation
- เครื่องที่รัน WebGL ไม่ได้: hero ใช้รูปนิ่ง `mansion.jpg` แบบเดิม (ไม่มีร่างที่เดินเข้ามา และไม่มีตอนจบกระจก) ส่วนกล้องแฟลชและเสียงยังทำงาน เพราะไม่ต้องใช้ WebGL
- ฉาก hero หยุด render เมื่อเลื่อนพ้นจอหรือแท็บถูกซ่อน
- เสียงหยุดเมื่อออกจากหน้า `/`
- เพิ่ม `three` เป็น dependency ได้ โหลดแบบ lazy หลังข้อความและปุ่ม hero แสดงแล้ว

## ส่วนที่ปล่อยให้ผู้สร้างตัดสินใจ

- โครงสร้างไฟล์/คอมโพเนนต์ ชื่อ key ใน `localStorage` และการแยก logic ออกมาทดสอบ
- จำนวนระยะที่ร่างเดินเข้ามา (ม็อกใช้ 6 ระยะก่อนหายไป) และระยะห่างแต่ละขั้น
- โอกาสสุ่มเสียงต่อการแตะ/เลื่อน และความดังของเสียง (เงียบพอให้ต้องตั้งใจฟัง)
- การออกแบบผี เสียง และฉาก ตราบที่ไม่ผิด anti-goals
