# แจกบัตรด้วยการสแกน QR — เอกสารออกแบบ

วันที่: 2026-11-08 · สถานะ: รออนุมัติ (ผ่าน builder check แล้ว)

## ทำไปเพื่ออะไร

วันงานมีโต๊ะแจกบัตรกระดาษ นักศึกษาเดินมายื่น **หน้าบัตรในมือถือ** ตอนนี้ทีมงานต้องพิมพ์รหัสนักศึกษาหรือเลขบัตรในหน้า `/admin/orders` กดค้นหา หาแถว แล้วกด "รับบัตรแล้ว" ซึ่งช้าเมื่อคนต่อคิวยาว เจ้าของงานอยากให้ **หาคนได้เร็วขึ้นด้วยการสแกน** ทีมงานใช้ **มือถือ** สแกน QR บนหน้าบัตรของนักศึกษา

## เป้าหมาย

1. หน้าบัตรของผู้ซื้อ (`/ticket/[studentId]`) แสดง QR ให้ทีมงานสแกน
2. หน้าใหม่ใน admin สำหรับสแกนด้วยกล้องมือถือ: สแกน → **เห็นชื่อกับเลขบัตรก่อน** → ทีมงาน **กดยืนยัน** แจกบัตร → กล้องพร้อมสแกนคนถัดไป
3. กรณีที่ห้ามแจกต้องเห็นชัด: รับบัตรไปแล้ว, บัตรถูกยกเลิก, ไม่พบบัตร

## สิ่งที่ไม่ทำ (non-goals)

- ไม่แก้ backend หรือ API — ทีม backend เป็นอีกทีม (ใช้ `GET /api/admin/orders?q=` และ `POST /api/admin/orders/{id}/pickup` ที่มีอยู่)
- ไม่ติ๊ก "รับบัตรแล้ว" อัตโนมัติตอนสแกน (เจ้าของงานเลือกให้กดยืนยันเอง)
- ไม่ลบหรือเปลี่ยนหน้า `/admin/orders` เดิม — ยังใช้ค้นแบบพิมพ์ ยกเลิกบัตร ดูสลิป และยกเลิกการติ๊กรับบัตรได้เหมือนเดิม
- ไม่ทำ QR ที่ลงลายเซ็น/กันปลอม (ดูข้อจำกัด)

## สิ่งที่ห้ามเกิด (anti-goals)

- **แจกบัตรซ้ำ:** คนถือรูปแคปหน้าบัตรของคนที่รับไปแล้วมารับอีก ต้องไม่มีปุ่มแจก และต้องเห็นคำเตือนชัด
- **แจกผิดคน:** ระบบต้องใช้รายการที่ `student_id` ตรงกับ QR **ทุกตัวอักษร** ห้ามใช้ผลค้นหาบางส่วน (API `q` ค้นแบบบางส่วนได้)
- **ช้ากว่าเดิม:** ถ้าสแกนแล้วต้องกดหลายขั้นหรือรอโหลดนาน ถือว่าล้มเหลว
- **ใช้ไม่ได้บน iPhone:** ทีมงานอาจใช้ iPhone หรือ Android ต้องสแกนได้ทั้งสองแบบ

## ข้อจำกัด

- โปรเจกต์: Next.js 16.4.5 App Router, React 19.3, TypeScript (อ่าน `node_modules/next/dist/docs/` ก่อนใช้ API ของ Next ตาม `AGENTS.md`)
- **กล้องในเบราว์เซอร์ใช้ได้เฉพาะ HTTPS** (หรือ `localhost`) — เว็บที่ deploy สำหรับวันงานต้องเป็น HTTPS
- `BarcodeDetector` ไม่มีใน Safari บน iOS จึงต้องใช้ไลบรารีถอด QR ที่ทำงานในเบราว์เซอร์ได้ทุกเครื่อง
- ข้อมูลบนหน้าบัตรเปิดดูได้ด้วยรหัสนักศึกษาอยู่แล้ว (`/ticket/[studentId]` ไม่ต้อง login) QR จึงไม่ได้เปิดเผยอะไรเพิ่ม และไม่ได้กันการปลอม — ทีมงานยังต้องดูชื่อบนจอให้ตรงกับคนตรงหน้า
- ข้อความบนเว็บเป็นภาษาไทย
- admin ใช้ token ใน sessionStorage และ helper เดิมใน `lib/api.ts` (`api.orders`, `api.pickup`) โดย 401 จะพากลับหน้า login อยู่แล้ว

## รายละเอียดที่เจ้าของงานตัดสินใจแล้ว

- นักศึกษายื่นหน้าบัตรในมือถือ ทีมงานใช้มือถือสแกน
- สแกนแล้ว **แสดงชื่อและเลขบัตรก่อน** แล้วทีมงาน **กดยืนยัน** จึงบันทึกว่ารับบัตรแล้ว
- เห็นชอบ flow ในม็อก (`.superpowers/brainstorm/98990-1794131808/content/admin-scan-flow.html`): หน้าบัตรมี QR → หน้ากล้อง → การ์ดผล "ยืนยันแจกบัตร 012" → กรณีเตือน 3 แบบ
- **ดูแค่ชื่อกับเลขบัตร** ไม่แสดงรูปสลิปบนการ์ดผล (สลิปถูกตรวจตอนซื้อแล้ว สลิปมีปัญหาจะถูกยกเลิกบัตรก่อน) — ข้อความเตือนในหน้า `/admin/orders` เดิมไม่ต้องแก้
- **วันงานมีมือถือสแกนหลายเครื่องพร้อมกัน** → ตอนกด "ยืนยันแจกบัตร" ต้องดึงสถานะล่าสุดของบัตรนั้นอีกรอบก่อนบันทึก ถ้าระหว่างนั้นอีกเครื่องแจกไปแล้ว ให้เปลี่ยนเป็นการ์ดส้ม "รับบัตรไปแล้ว" แทนการบันทึก (backend ไม่ได้รับประกันว่าจะปฏิเสธการติ๊กซ้ำ — เอกสารระบุ 409 เฉพาะบัตรที่ถูกยกเลิก) ยอมช้าลงเสี้ยววินาทีเพื่อปิดช่องแจกซ้ำ ช่องที่เหลือคือสองเครื่องกดในเสี้ยววินาทีเดียวกันพอดี ซึ่งรับได้

## รายละเอียดที่ Claude ตัดสินใจ (เจ้าของงานเห็นในม็อกแล้วไม่ค้าน)

- **QR เก็บแค่รหัสนักศึกษา** (ตัวเลข 10 หลัก) ข้อความล้วน ไม่ใช่ URL
- **หน้าใหม่** `/admin/scan` เพิ่มในเมนู admin ชื่อ `สแกนแจกบัตร` (เมนูเดิมยังอยู่ครบ)
- **หลังกดยืนยัน** กล้องพร้อมสแกนคนถัดไปทันที ไม่ต้องกดเปิดกล้องใหม่
- **ปุ่ม "พิมพ์ค้นหาแทน"** ในหน้าสแกน สำหรับตอนกล้องมีปัญหาหรือมือถือนักศึกษาแบตหมด — กรอกรหัสนักศึกษา 10 หลักแล้วได้การ์ดผลแบบเดียวกับการสแกน
- **ปุ่ม "ไม่ใช่คนนี้ / สแกนใหม่"** บนการ์ดผล ปิดการ์ดแล้วกลับไปสแกนโดยไม่บันทึกอะไร
- **ตีความผลลัพธ์จากรายการที่ `student_id` ตรงเป๊ะ:**
  - มีรายการ `active` ที่ยังไม่รับ → การ์ดเขียว + ปุ่ม `ยืนยันแจกบัตร {เลขบัตร}`
  - มีรายการ `active` ที่ `picked_up_at` ไม่ว่าง → การ์ดส้ม `รับบัตรไปแล้ว {เวลาไทย}` ไม่มีปุ่มแจก
  - มีแต่รายการ `cancelled` → การ์ดแดง `บัตรถูกยกเลิก` พร้อมเหตุผล ไม่มีปุ่มแจก
  - ไม่มีรายการ หรือ QR ไม่ใช่ตัวเลข 10 หลัก → การ์ดแดง `ไม่พบบัตรของ QR นี้`
- **ระหว่างแสดงการ์ดผล** ไม่รับผลสแกนใหม่ (กันสแกนซ้ำรัว ๆ จาก QR เดิมที่ยังอยู่หน้ากล้อง)
- **รหัสเดียวมีหลายรายการ** (เช่นเคยถูกยกเลิกแล้วซื้อใหม่): ใช้รายการ `active` ก่อน ถ้าไม่มีจึงแสดงรายการ `cancelled` ล่าสุด
- **QR แสดงบนหน้าบัตรเสมอ** แม้รับบัตรไปแล้ว (สแกนแล้วทีมงานจะเห็นการ์ดส้มอยู่ดี)
- **error เครือข่าย** ตอนค้นหรือตอนยืนยัน: แสดงข้อความพร้อมปุ่มลองใหม่บนการ์ดเดิม ไม่ต้องสแกนใหม่

## ส่วนที่ปล่อยให้ผู้สร้างตัดสินใจ

- ไลบรารีสร้าง QR (หน้าบัตร) และไลบรารีถอด QR จากกล้อง (ต้องทำงานบน iOS Safari และ Android Chrome)
- ขนาด/ตำแหน่งของ QR บนหน้าบัตร (ต้องสแกนง่ายจากระยะยื่นมือถือให้ดู)
- เลือกกล้องหลังเป็นค่าเริ่มต้น การขอสิทธิ์กล้อง และข้อความเมื่อไม่ได้รับสิทธิ์
- ข้อความแจ้งผลหลังยืนยันสำเร็จ และการจัดการ error เครือข่าย (ต้องลองใหม่ได้โดยไม่ต้องสแกนใหม่)
- หน้าตาและ layout บนมือถือ ให้เข้ากับธีม admin เดิม
